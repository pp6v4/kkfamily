# 代码与设计差异核对（2026-08-31）

基线：b424ec1；本次以apps/api/src、Prisma模型、apps/client/src和infra配置为证据。设计见design/contract-details.md及R01～R03确认记录。设计原型不是业务实现；下表的“有代码”不等于真机验收通过。

## 闭环结论

目前不能认定全项目逻辑闭环。核心风险不只是页面未做：账号自动创建不同家庭、模块权限未执行、聚合入口泄露行程、两人同菜重复计料、缺少快照和并发保护，会使已经存在的页面产生错误结果。先补共享账号与权限基础，再完成餐饮购物和行程协作，不能把未实现模块包装成可用。

## 本轮开始实施的范围

统一家庭头校验和模块鉴权；成员邀请、角色/显式权限、停用和管理员转让；取消新账号自动建家，提供创建/加入入口及真实成员管理页面；日历按来源过滤并处理跨度；构建上下文排除私密文件。后续餐点快照/份数/库存事务、行程小组/地图/照片和家庭扩展仍在完整目标范围内，不删除这些差异。

测试分层记录：纯权限算法、真实Nest HTTP与独立PostgreSQL集成、客户端构建、微信双账号/真机。只将实际运行覆盖项标通过，不用模拟对象测试冒充数据库并发验收。生产数据与服务不在本次测试写入范围。

## 2026-09-01 实施进展与范围更新

已实现共享家庭邀请、成员角色/显式权限/停用/管理员转让，统一后端家庭头和模块鉴权；客户端取消自动创建不同家庭，提供显式创建/加入和真实成员管理；日历按来源权限聚合实际餐点和行程。

餐饮主链路已加入同日同餐唯一、多人同菜一份、实际份数、菜单确认/重新打开/烹饪/完成状态、不可变版本快照、未知及不同单位库存判断、调料有/无/未知、服务端缺料重算和快照来源幂等购物项。购物购买记录及复购保留历史。

用户于2026-09-01确认一期不做“完成做饭自动减库存”和“购物完成自动加库存”。当前完成餐点和勾选购物均不修改库存，库存只允许显式人工维护；详见 `design/decisions-20260901.md`。这不是待修缺陷，未来是否加入由实际使用痛点决定。

尚未闭环：菜谱编辑和图片发布校验、行程成员/状态/分组、地图路线、酒店交通、私有照片，以及待办/收藏/档案/看板/通知。当前仍不是完整正式版。

工程依据：[Nest守卫与依赖注入](https://docs.nestjs.com/guards)、[Prisma 6事务与冲突重试](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions)。权限属于服务端业务约束；关键并发写入在事务内重新检查并使用Serializable及有限冲突重试。
