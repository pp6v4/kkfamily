# COS 接入检查单

## 2026-09-18 实际检查

服务器 `/opt/family-life/apps/api/.env` 和正在运行的API都缺少 `COS_SECRET_ID`、`COS_SECRET_KEY`，且未启用COS驱动；桶名和地域正确。检查仅输出存在性和匹配结果，不输出密钥。这不是单纯重启可以解决的问题。

## 用户准备

1. 如已有项目专用腾讯云子账号密钥，直接使用；没有则在访问管理CAM创建项目专用编程访问子账号。不要使用主账号全权限密钥。
2. 授权仅限北京桶 `family-life-pp6v4-1303887403` 的 `households/*` 对象前缀，使用上传、读取、读取元信息需要的权限。不要授予删除桶、全云管理员或公开写入权限。当前代码调用PutObject、HeadObject、GetObject并指定对象ACL=private；若云端要求额外ACL权限，应核对拒绝原因并限定私有ACL，不直接扩大为全权限。
3. 保持桶私有读写，不为解决403而改成公有读或公有写。当前图片通过同域后端授权和短时链接读取，无需将密钥放入小程序、无需前端直连COS。
4. 在自己的SSH终端运行 `nano /opt/family-life/apps/api/.env`，只把 `COS_SECRET_ID`、`COS_SECRET_KEY` 的值填进去；不要把完整env粘贴到聊天、Git或截图中。不要改动数据库、微信和JWT配置。
5. 当前 `COS_BUCKET=family-life-pp6v4-1303887403`、`COS_REGION=ap-beijing` 保持不变。先保留 `MEDIA_DRIVER=disabled`，填完后告诉我“COS已填好”，由后续验证步骤启用并重建受影响服务，不重建数据库。
