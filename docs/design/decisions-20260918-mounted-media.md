# 挂载存储接入决策（实施中，尚未启用）

## 当前证据与目标

用户确认新桶为 `familylife-1303887403`，不沿用旧 COS 桶。服务器实测
`/mnt/family-life-cos` 为 `fuse.cosfs` 挂载点；API 容器尚无该目录映射。
现有 ObjectStorageService 仅支持 disabled、测试 memory 和密钥 COS SDK。
因此控制台挂载成功不等于业务照片已可上传。

## 保持的业务约束

- 小程序仍只通过同域 `/api/` 上传及读取；不开放 Nginx 静态照片目录。
- 家庭、菜谱、行程成员校验及 60 秒读取能力链接保持不变。
- 只接受现有 JPG/PNG/WebP 与 8MB 上限；完成上传仍校验大小、类型和 SHA-256。
- 数据库、Redis、备份目录不迁入 COS。无自动库存增减，无微信订阅提醒。

## 实施门槛

1. 新增独立挂载目录驱动，不假装成 SDK 驱动；disabled 仍为默认值。
2. API 容器映射已存在挂载点，不允许 Docker 自动创建空目录兜底。
3. 每次操作校验精确挂载点为可写 fuse.cosfs；普通目录、其他 FUSE、只读或歧义挂载拒绝。
4. 文件键仅允许服务端生成的家庭资源路径，禁止穿越、符号链接逃逸及任意文件覆盖。
5. 校验不能只做一次路径检查：读写持有挂载内目录/文件句柄，防检查后掉线写到系统盘。
6. 重挂载后旧容器 bind mount 可能失效；验证新挂载并重建 API，不能宣称宿主机恢复即容器恢复。
7. 保持图片可被独立读取；元数据方案需保证中断/并发写不会确认不完整内容。
8. 开发测试后做 Linux 实挂载读写、掉线拒绝、私有权限及完整上传确认链路验证。
