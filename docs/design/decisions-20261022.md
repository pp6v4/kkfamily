# 2026-10-22 体验版测试与正式上线清理决定

确认来源：本任务中用户明确提出：“你后面都直接提交版本，我在体验版测，要不然咋测试。我就生产环境直接测试。后面正式上线，你清库然后上线”。这是后续交付方式和正式上线准备的决定，不是本次操作已经成功的回执。

## R07：后续修复直接交付体验版（U）

1. 修复按功能批次完成必要的源码、构建及相关隔离数据库检查；配套API有变化时，先备份并部署兼容后端和迁移，再上传客户端。
2. 后续客户端版本直接上传并设为体验版，供用户在手机中测试；测试连接既有生产后台，不再要求用户反复导入本地构建目录。
3. 单独记录Git提交、API镜像、迁移、备份、客户端构建、微信上传和体验版标记的实际结果。某一项成功不推导其他项已完成。
4. 真实账号、业务数据及照片由用户实际操作验收。自动测试、模拟器和上传成功均不能替代手机验收，不为凑验收结果随意创建生产演示记录或改变家庭成员权限。
5. 体验版交付不是正式提交审核或正式发布；后两项仍需在正式上线流程中单独确认、执行和保留平台回执。微信订阅、自动库存等已延期范围不因此恢复。

本决定承接并调整[R06批次交付](decisions-20260910.md)和10月21日用户要求上传供实测的交付节奏。仍按必要改动成批验证，不为没有变化的组件反复上传部署；保留旧包和独立构建目录，避免覆盖正在对照的历史产物。

## R08：正式上线前清理测试数据（U，执行范围待确认）

用户希望正式上线前清库，再开始正式使用。该步骤在后续正式上线时执行；当前不清库、不删除媒体，不用重建数据库或清除持久卷代替业务清理。

执行前必须完成以下准备，并将准确清单交用户当时确认：

| 准备项 | 必须明确的内容 |
| --- | --- |
| 清理范围 | 实际目标数据库、表/记录筛选条件、关联顺序；哪些是测试数据、哪些需保留；不能仅写“全部业务数据” |
| 保留范围 | 管理员及其他账号、家庭关系、角色/模块权限、基础分类/模板、生产配置等分别列明保留或重建方案；此处不预先批准任何一类删除 |
| 媒体关联 | 若需清理COS对象，先解析对应测试记录及对象清单；不按整个桶、宽泛前缀或未知目录批量删除照片 |
| 备份与恢复 | 在受保护位置保存数据、必要配置及加密恢复条件，检查备份完整性并在隔离环境验证可恢复；秘密和生产备份不进入Git |
| 执行窗口 | 确认停止或限制测试写入、最终备份时点、精确清单和失败恢复办法，避免清理期间产生不一致引用 |
| 后置核对 | 逐项核对清理数量、保留账号/权限可用、关联和媒体一致性、健康及体验版/正式发布状态；如实报告删除及恢复方式 |

清理授权不得扩展成修改既有schema、改历史迁移、`migrate reset`、`down --volumes`、宽范围prune或清空整个对象桶。当前业务中的纪念日、菜谱和行程历史仍遵守各自软归档、快照及权限规则，不因未来清库决定而提前物理删除。
