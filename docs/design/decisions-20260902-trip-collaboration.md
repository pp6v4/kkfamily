# 行程协作一期实现决策（2026-09-02）

## 范围

本轮只闭环“谁能进入某趟行程、谁能协作、完成后谁还能查看、不同准备方如何分工”。地图节点、路线动画、住宿、交通和行程相册继续作为下一阶段，不用占位数据冒充完成。

## 访问与状态

- 创建者自动成为 `TripMember(OWNER, ACTIVE, canEdit=true)`。
- 家庭角色和行程成员是两层权限：即使是家庭管理员，未加入该趟行程也不能读取标题、地点、日历投影或行李。
- `ACTIVE` 可以按 `canEdit` 协作；正常完成行程后统一转为 `HISTORY`，保留只读历史；主动撤销转为 `REVOKED`，立即失去列表、详情、日历和行李访问。
- 行程至少保留一名未撤销的 `OWNER`。成员、行程和准备小组写入均带版本号，旧页面提交返回409，不覆盖新数据。

## 分工与行李

- `TripPreparationGroup` 表示本次行程里的准备方，例如“我们家”“朋友A家”，不暴露或依赖朋友的真实家庭档案。
- 行李可以同时指定准备小组和组内负责人；指定个人时必须是当前有效行程成员，指定小组后个人还必须属于该组。
- 撤销成员前检查其未完成责任；默认拒绝，用户明确确认后才清空责任并撤销访问。
- 行李更新使用版本号；移除写入 `excludedAt`，不物理删除。套用模板保存来源模板名和来源项名快照，后续模板改名/归档不改变既有行程的来源展示。

## 一期明确不做

- 做饭完成不自动扣库存，购物完成不自动入库存；库存仍为人工维护和辅助判断。
- 本轮不部署生产、不写生产数据库；验证只在独立Docker网络和独立PostgreSQL测试schema执行。
