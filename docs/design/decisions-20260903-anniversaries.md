# 纪念日一期实现决定（2026-09-03）

## 背景

家庭日历原来只把纪念日保存为一次性`CalendarEvent`，没有编辑、删除和重复规则，无法满足长期实际使用。农历生日此前明确未进入一期确认范围。

## 本期实现

- 纪念日使用独立`Anniversary`模型，日期按家庭本地公历`YYYY-MM-DD`保存，不受服务器时区改变影响。
- 创建时由用户选择`YEARLY`（每年）或`ONCE`（仅一次），界面默认每年但允许立即切换。
- 2月29日每年事件由用户选择非闰年规则：2月28日、3月1日或当年跳过；不在服务端暗自决定。
- 列表按查询年份动态生成发生日期，不预先写入未来多年的冗余行。
- 修改使用`expectedVersion`乐观锁；删除采用`archivedAt`软删除；创建、修改和删除均记录不含备注正文的审计日志。
- 旧的无来源纪念日事件在迁移时转为`ONCE`，保留原来的上海本地日期；无法对应家庭成员的异常旧行保留为只读兼容事件，避免静默丢失。

## 暂不实现

- 农历换算、农历生日。
- 单独取消或改期某一年的重复实例。
- 自动计算“第几年”或向微信发送纪念日订阅消息。

这些能力以后依据真实使用痛点追加，不影响当前公历纪念日闭环。
