# 扣扣的家：页面与交互设计补充

版本：2026-08-31 / 评审稿。依据：U01～U13、D01～D15。本文描述目标交互，不代表全部页面已开发。产品规则中的乙方建议仍需评审，不能据此变更真实用户权限。

## 1. 信息架构与呈现约定

底部固定五项：**日历 / 吃什么 / 去露营 / 买东西 / 我的家**。不另加第六项，也不将家庭日历移入“我的家”。详情页保留返回入口及上页日期、筛选、滚动位置；编辑页离开前有未保存提示，不能无声丢弃。

视觉方向是温暖、清新、可爱，不复制具体游戏素材。奶油底、叶绿主操作、圆角卡片；禁止用一串大 emoji 代替信息层级。页面主标题、卡片标题、正文、辅助文案依次24/18/16/14px等效大小，实际小程序采用rpx并做真机校验。正文对比度目标4.5:1；状态同时有文字，不只依赖红绿颜色。有效点击区域至少44×44px等效大小；窄屏表单改纵向，数量和单位允许并列，名称不能被压成单字列。

小程序遵守系统导航栏与安全区。列表分页加载失败保留已加载内容；不将刷新失败呈现为清空清单。提交成功由服务端确认，不能点击后无条件显示“已保存”。原型的成功仅代表内存演示已完成，顶部始终显示“数据不保存”。

## 3. 共用状态、动作与文案

| 状态 | 展示及允许动作 | 必须保持的约束 |
| --- | --- | --- |
| 初次加载 | 骨架与“正在加载”，不展示假业务记录 | 请求完成才渲染数据；不能拿演示数据补空 |
| 空列表 | 解释为何为空，有编辑权才给新建按钮 | 模板空态：“还没有自定义模板，先写下经常带的东西” |
| 无权限/已撤权 | “暂时无法访问，请联系行程管理员”及返回 | 不显示行程标题/图片/成员姓名；缓存清除 |
| 读取失败 | 保留上次数据并标未更新；重试 | 不把网络错误变成“没有行李” |
| 校验失败 | 字段下方原因，焦点移到第一个错误 | 输入原样保留，不只显示一闪而过的提示 |
| 提交中 | 禁止重复提交；仍可看当前表单 | 超时结果未知时查幂等结果，不能再造记录 |
| 保存成功 | 简短成功提示，更新列表/计数后返回 | 服务端真实返回内容为准；演示与生产分开 |
| 版本冲突 | 显示最新版本、保留本地草稿，手动选择重填 | 不无条件覆盖配偶/朋友刚做的修改 |
| 离线 | 允许看已获准缓存且标时间，写操作提示联网 | 不排队执行未来可能越权的离线操作 |
| 离开未保存 | “继续编辑 / 放弃本次修改” | 默认继续编辑；返回手势与导航按钮同规则 |

归档/移除均先展示对象名称、范围及后果，再确认。模板归档不动历史行程；行程移除只影响本次，保留来源排除标记。此处的产品确认框不是授权助手删除用户文件。

## 4. 自定义行李：完整流程与边界

```text
去露营 → 行李模板 → 新建空白模板 → 自己命名、逐项填写 → 保存
行程详情 → 本次行李 → 套用模板 → 预览新增/跳过 → 确认
本次行李 → 编辑本次物品 / 分配小组与负责人 / 勾选已准备
```

### P19：编辑模板

不提供默认烧烤物品，不根据模板名称推荐/补齐物品。用户写“烧烤”，物品写“1、2、3”，保存的就只有这三项。名称只作普通文本字段；同名模板不自动合并。至少1件有效物品；空名称拒绝；增加的半填写行要指出错误，不能悄悄过滤丢失数量备注。

数量可不填；填了必须是正数，单位可选。模板不保存本次行程负责人或已准备状态；这些属于行程实例。修改物品保留稳定ID，不能按数组下标重新生成身份。移除模板项先确认并软归档；后续新行程不再套入它，历史快照不变。

### P20：套用前预览

进入后可以选多个模板。逐模板显示有效项数、预计新增、因已存在或明确移除而跳过的数量。首次3项应“新增3，跳过0”；重复套用应“新增0，跳过3”。两模板同名物品来自不同来源，显示两项；不凭名字合并。

预览后服务器版本改变，重新计算再确认，不沿用过期数量。主操作为“加入本次行程”；没有可新增项时显示原因，不制造成功假象。已排除项在“已移除”中通过“重新加入”显式恢复；重新套用不复活。工程建议见D08。

### P21/P22：本次清单与责任

清单显示名称、可选数量单位、历史来源模板名、负责人和“待准备/已准备”。进度分母只含本次有效项，不含排除项；空清单显示0项而非100%。从模板复制后改行程数量或名称不修改模板；后来改模板名、物品名或归档模板也不改变本次快照。

责任小组由用户命名，“我们家/朋友家”仅是可选示例，不按账号家庭关系自动建组。小组必须属于该行程，负责人必须属于该行程；选择小组后仅列该组成员。换组后原负责人不在新组时清空并提示。取消个人负责人可保留小组；取消小组可保留合法行程负责人。被指派负责人不自动获得编辑权。

手工加项只加入本次行程，不自动保存成模板。新增项初始待准备、未分配。已准备可以取消勾选，按钮明确写“改为待准备”；不会删除物品。只读参与者看清单和分配，不允许编辑、套用或勾选。

## 5. 关键跨模块流程

| 流程 | 用户看到的确认 | 成功出口 | 失败保留 |
| --- | --- | --- | --- |
| 日历创建晚餐→点菜→汇总 | 日期餐次、菜名、实际制作份数 | 同一餐点与日历记录互相跳转 | 原日期和已选菜 |
| 缺料→购物 | 全部材料仍可查看，只导入勾选项 | 返回购物列表并标餐点来源 | 比对结果及已勾选项 |
| 确认烹饪完成→库存 | 提示库存仅辅助；可确认实际消耗 | 完成一次，只生成一次有效流水 | 人工填写的消耗数量 |
| 行程→日期变更 | 新日期与受影响提醒 | 日历跨度、详情、提醒一致 | 路线、行李、相册不重建 |
| 行程→准备小组 | 组名、选中成员和物品范围 | 清单分工变化，不授予家庭数据权 | 原分工与编辑草稿 |
| 收藏→菜谱草稿 | 预填来源，要求补食材做法 | 菜谱草稿，不直接发布 | 原收藏始终保留 |
| 待办取消→提醒 | 明确取消的事项 | 待发通知取消，历史记录保留 | 失败不显示已取消 |

## 6. 原型覆盖与验证边界

[自定义行李交互原型](packing-prototype/index.html)对应P18～P22的核心交互，并演示P23的已有小组/成员分配。小组创建本身只在上述设计中定义，原型不假装实现。

原型仅本地内存：模板初始为空；“周末出行”及成员、小组是明确标注的虚构演示数据；刷新后重置；不调用微信、COS、数据库或生产API。演示只读切换不修改真实账号权限。它不是替换微信小程序的构建产物。

自动用例检验的是原型状态转换，浏览器检查的是原型表单和布局；都不能将A01～A42的生产业务验收改成PASS。其他P页面已有交互规范，完整视觉效果和真机实现仍需后续逐页检验。
