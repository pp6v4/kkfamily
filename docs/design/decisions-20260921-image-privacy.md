# 照片隐私处理补齐（开发验证中）

## 原始缺口

D10要求默认移除EXIF定位信息；旧实现只检查文件签名并存储原始字节。私有桶与短期链接解决访问权限，不等于删除元数据。

## 实施

- 服务端使用固定版本 sharp 0.35.4 解码并重新编码 JPEG/PNG/WebP，默认不保留 EXIF、XMP、IPTC 和 ICC；先按EXIF方向旋转像素。
- 输入保留8MiB上限，解码最多5000万像素；最多同时处理2张，超额返回503，不建立无限处理队列。
- 输出保留8MiB上限。拒绝损坏、格式不符、多帧图片和处理失败，不回退存储原图。
- `declaredBytes`记录请求原始大小，`uploadedBytes`记录处理后的大小；摘要、对象存储和最终MediaAsset均指向处理后的字节。
- 确认上传比较uploadedBytes而非declaredBytes。重复提交原图重新执行同一处理，比较处理结果保持幂等。
- 现有客户端使用上传响应中的摘要确认，无需让客户端猜测清理后的大小或摘要。
- 本批不批量改写或删除已有对象；历史照片是否需要处理须先检查并明确列出范围。
