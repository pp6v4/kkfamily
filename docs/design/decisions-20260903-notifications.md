# 站内提醒与微信订阅边界（2026-09-03）

## 已实现的可靠主链路

- 待办创建及每次内容、负责人、提醒时间或状态变化，都在同一数据库事务中写脱敏 outbox，并使旧提醒任务及旧站内消息失效。
- 有负责人、提醒时间且状态为待开始/处理中时，按待办版本创建唯一站内任务；完成、取消、归档或改派后不再投递旧提醒。
- 独立 `notification-worker` 每30秒领取到期任务，发送前重新检查成员状态、待办版本、负责人、业务状态、来源模块权限和个人提醒设置。
- 任务领取使用状态条件更新；进程异常后5分钟回收卡住任务。失败按1、5、15分钟重试三次，仍失败才标记失败。
- 站内消息数据库只保存通用标题和来源标识；列表重新授权后才读取真实待办标题。撤权或来源失效后消息被隐藏。
- 收件箱已读和个人偏好均有版本冲突保护；默认安静时段22:00～08:00，到期任务顺延到次日或当日08:00。

## 微信订阅边界

- 页面只在用户明确点击“主动申请”后调用微信订阅授权，拒绝或封禁结果只记录回执，不影响待办保存和站内提醒，也不自动再次弹窗。
- 未配置 `WECHAT_TASK_REMINDER_TEMPLATE_ID` 时，接口明确返回微信订阅不可用，页面不伪造模板或发送成功。
- 当前完成的是订阅申请/回执和站内降级；真正调用微信发送接口仍需取得正式模板ID、确认模板字段并在真机/生产环境联调。此前不得宣称微信外部消息已送达。
- 微信返回 `accept` 仅代表一次授权回执，发送接口成功也不代表用户已读；这些状态不得混为一谈。
