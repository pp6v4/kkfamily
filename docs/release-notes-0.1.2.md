## 本轮四项问题

| 编号 | 原问题 | 已修复内容 | 手机怎么测、预期是什么 |
| --- | --- | --- | --- |
| B01 | 配料无法删除 | 食材、调料逐行“移除”；仅剩一行时可“清空”，调料可全部不填 | **吃什么 → 菜谱 → ＋ 添加菜谱 / 编辑菜谱**：填两行食材、两行调料，分别移除，再清空最后一行；补回至少一项有效食材并保存，重新打开应只保留所填内容。清空只改草稿，不自动保存或删除整道菜 |
| B02 | 保存菜品时报“图片存储尚未配置” | 修复服务器COS缓存空间门槛引起的写入故障；区分未配置与实际上传/读取失败 | 在菜谱编辑页填菜名、食材和做法，**不选图保存草稿**应成功；再选成品图保存，返回后封面可加载。**发布仍需要就绪封面图**；缺图发布应提示缺封面，不应误报存储未配置。上传失败时输入应保留，不应伪成功 |
| B03 | 找不到点菜入口 | 明确日期、餐别和“创建这顿餐点，开始点菜”入口；草稿/无已发布菜谱/缺权限分别提示 | **吃什么 → 去点餐**：选日期和餐别，创建餐点，对已发布菜谱点“点这道菜”，在待做菜单核对；再“撤回我的选择”，应只撤回本人。别人已点的菜显示“我也想吃”，不会自动增加制作份数。没菜时按“去准备并发布菜谱”指引操作 |
| B04 | 日历纪念日无法删除 | 日期列表直接提供“删除纪念日”；新版系列与旧版独立纪念日分别软归档 | **日历 → 对应日期 → 当天安排**：点“删除纪念日”后先取消，记录应保留；再次确认后应从日历消失。**每年重复项删除整个系列，所有年份都不再显示**，不是仅删除当天；归档保留历史，不会连带删除餐点或行程 |

权限前提：菜谱录入/图片/发布需要菜谱编辑权；点菜需要菜谱查看和餐点编辑权；纪念日删除需要家庭共享`calendar:EDIT`。缺权时联系管理员授权，不通过关闭服务端校验解决。

## 随0.1.2一起交付的此前收束修复

这些变更此前在源码中完成，本次才随新后端及客户端交付，不当作0.1.1已经具备的能力。

| 内容 | 核对重点 |
| --- | --- |
| 管理者移除整道菜 | 待做菜单中管理者可用“移除本餐这道菜”；已确认餐单须先显式重新打开。会移除所有人对该菜的本餐选择，须阅读确认框；旧快照、变更审计及其他菜保留 |
| 只读查看完整做法 | 点菜、菜谱库和待做菜单可查看“用料与做法”；有查看权不意味着有编辑权。已确认餐单显示冻结快照，不被之后修改的菜谱覆盖 |
| 已结束行程收缩授权 | 合法行程OWNER在完成/取消后仍可撤销访问或关闭加照片权限；不能借此恢复授权、重开业务编辑或改写历史分工。请只对明确同意测试的协作关系操作 |
| 待办编辑 | 说明可清空；不改派时保留原负责人，包括已经停用的负责人。选择“保持原负责人”不会默改为列表第一人；实际改派仍需管理权和有效成员；不改日期则保留原时间精度 |
| 看板日期范围 | 按上海自然日生成近30/90/365天边界，不因手机时区不同而换一天；仍按来源权限过滤数据 |

一期继续不自动扣减做饭库存、不自动将购买加入库存；微信订阅推送、账本预算和真实道路导航仍不在本次交付范围。
